# React Native and Expo: Rapid-Fire Interview Questions

> How to use: cover the answer, say yours out loud, then check. Deeper explanations live in the topic files linked under each section.

## React Native fundamentals (see [file](01-react-native-fundamentals.md))

**Q1. What is React Native in one sentence?**
A framework that runs React and TypeScript code in a JS engine on the device and renders real native iOS and Android views, so one codebase produces two native apps.

**Q2. Is a React Native app a WebView?**
No. There is no HTML or browser engine; `View` and `Text` become `UIView`/`ViewGroup` and native text views. WebView-based frameworks are Cordova, Capacitor and Ionic.

**Q3. Which threads matter in a React Native app?**
The JS thread (React rendering and your logic), the UI or main thread (native views, touches, native animations) and background threads (Yoga layout, image decoding, native work). A blocked JS thread delays taps; a blocked UI thread freezes the app.

**Q4. What was the bridge?**
The legacy asynchronous, batched channel that serialized every JS-to-native message to JSON. It cost serialization time, allowed no synchronous calls, initialized all native modules at startup and had no type contract.

**Q5. Name the parts of the New Architecture.**
JSI (direct C++ calls from JS), Fabric (the C++ renderer), TurboModules (lazy, typed native modules), Codegen (native glue generated from typed specs) and bridgeless mode.

**Q6. When did the New Architecture become the default?**
In React Native 0.76 (Oct 2024). Expo SDK 52 enabled it for new projects and SDK 53 for all; SDK 54 was the last SDK with the legacy option, and RN 0.82+ supports only the New Architecture.

**Q7. What is Hermes?**
The JS engine built for React Native and the default since 0.70. It compiles JS to bytecode at build time, giving faster startup, lower memory use and smaller downloads.

**Q8. What is Yoga?**
The cross-platform C++ flexbox layout engine that computes the size and position of every view from your styles.

**Q9. React Native vs Flutter in two lines?**
React Native renders native platform views and reuses React/TS skills, with OTA updates for JS. Flutter draws every pixel with its own engine in Dart, giving identical UI everywhere but non-native widgets and no official OTA.

**Q10. What are the flexbox defaults that surprise web developers?**
`flexDirection: 'column'`, `alignItems: 'stretch'`, `flexShrink: 0`, `flex` takes a single number, and there is no cascade; only nested `Text` inherits text styles.

**Q11. What units does React Native use?**
Unitless density-independent pixels (points on iOS, dp on Android), plus percentages for some size properties. `PixelRatio` converts to physical pixels.

**Q12. ScrollView or FlatList for 500 transactions?**
FlatList: it virtualizes, rendering only items near the viewport, while ScrollView renders all 500 rows up front.

**Q13. How do you write platform-specific code?**
`Platform.OS`, `Platform.select({ ios, android, default })`, `Platform.Version` for OS-version checks, or separate `Component.ios.tsx` and `Component.android.tsx` files resolved by Metro.

**Q14. How do you handle safe areas?**
`react-native-safe-area-context`: `SafeAreaProvider` at the root, `SafeAreaView` with explicit `edges`, or `useSafeAreaInsets()`. The core `SafeAreaView` is iOS-only and deprecated in RN 0.81.

**Q15. Why does the Submit button need two taps while the keyboard is open?**
The scroll container's `keyboardShouldPersistTaps` defaults to `'never'`, so the first tap only dismisses the keyboard. Set it to `'handled'`.

**Q16. How do you support dark mode and accessibility basics?**
Read `useColorScheme()` to pick a theme and set `userInterfaceStyle` in the app config. For accessibility, give touchables `accessibilityRole` and `accessibilityLabel`, respect font scaling and keep touch targets at least about 44 points.

## Expo (see [file](02-expo-fundamentals.md))

**Q17. What is Expo?**
A React Native framework: Expo SDK modules, Expo CLI, Expo Router, Expo Go, development builds and EAS cloud services for building, submitting and updating apps.

**Q18. Expo Go vs a development build?**
Expo Go is a shared store app with a fixed set of native modules for one SDK. A development build is your own binary with `expo-dev-client`, your native dependencies and your config. Custom native code always needs a development build.

**Q19. When must you leave Expo Go?**
When you add native code it lacks, change config plugins, icon or permission strings, test your own scheme or universal links, or test remote push on Android (not supported in Expo Go from SDK 53).

**Q20. What is CNG?**
Continuous Native Generation: `ios/` and `android/` are generated by `npx expo prebuild` from the app config, config plugins and packages, so they can be deleted and regenerated instead of hand-maintained.

**Q21. What is a config plugin?**
A function that modifies the generated native projects during prebuild (Info.plist, AndroidManifest, Gradle, entitlements) through typed mods such as `withInfoPlist` and `withAndroidManifest`.

**Q22. app.json or app.config.ts?**
`app.json` for static config; `app.config.ts` when values depend on environment variables or build profiles, such as different bundle IDs for dev, preview and production.

**Q23. How do `EXPO_PUBLIC_` variables work?**
Expo CLI inlines them into the JS bundle at build time when referenced statically (`process.env.EXPO_PUBLIC_API_URL`). They are public: anyone can extract them from the app.

**Q24. Where do secrets go then?**
On your backend. The app calls your API, and the server uses the secret. Build-time secrets (such as a Sentry auth token) live in EAS environment variables with secret visibility.

**Q25. Why `npx expo install` instead of `npm install`?**
It picks package versions compatible with your Expo SDK and React Native version; `--fix` repairs mismatches across the project.

**Q26. How do you upgrade an Expo SDK?**
One SDK at a time: read the release notes, bump `expo`, `npx expo install --fix`, `npx expo-doctor`, update other native libraries, regenerate native projects, rebuild dev clients, test release builds, ship new store builds.

**Q27. What replaced "eject", `expo build` and `expo publish`?**
CNG plus config plugins replaced ejecting; EAS Build replaced `expo build`; EAS Update replaced `expo publish`.

**Q28. Which modules replace `expo-av`?**
`expo-audio` and `expo-video`.

## Navigation and deep linking (see [file](03-navigation-expo-router.md))

**Q29. Stack vs tabs vs modal?**
Stack for drill-down with back navigation, tabs for parallel top-level sections that keep their state, modal for a focused task presented over the current screen.

**Q30. How does Expo Router define routes?**
Files in `app/` are routes: `index.tsx` is a folder's default, `[id].tsx` is dynamic, `[...slug].tsx` catches all, `(group)` folders do not appear in URLs, `_layout.tsx` defines the navigator and `+not-found.tsx` handles unknown URLs.

**Q31. What type are route params?**
Strings (string arrays for catch-all routes), because they come from a URL. Convert and validate them, for example `Number(id)`.

**Q32. `push` vs `replace`?**
`push` adds a screen to the stack; `replace` swaps the current screen, used after login or after submitting a form so back does not return to it.

**Q33. How do you protect routes?**
`Stack.Protected guard={!!user}` in recent Expo Router versions (v5, SDK 53+), or a `<Redirect href="/login" />` in a group layout. The API still authorizes every request.

**Q34. How do you prevent back navigation after logout?**
Let the auth guard remove protected screens (protected groups), or call `router.dismissAll()` and `router.replace('/login')`. Also clear the query cache and stored tokens.

**Q35. Custom scheme vs universal links?**
A scheme (`myapp://events/42`) is easy but not unique to your app and often not clickable. Universal links (iOS) and app links (Android) use verified `https://` URLs that open the app if installed and the website otherwise.

**Q36. What files verify universal and app links?**
`/.well-known/apple-app-site-association` (Team ID plus bundle ID and paths) and `/.well-known/assetlinks.json` (package name and the SHA-256 fingerprint of the Play App Signing key), both served over HTTPS without redirects.

**Q37. How do you test a deep link on Android?**
`adb shell am start -W -a android.intent.action.VIEW -d "myapp://events/42" com.example.app` on a development build (Expo Go only knows `exp://`).

**Q38. Should you pass a whole object as a param?**
No. Pass the ID and fetch by ID: params are serialized strings, objects go stale and deep links cannot carry them.

**Q39. How do you make a deep-linked detail screen have a back button?**
Give the nested stack an initial route (Expo Router's `unstable_settings.initialRouteName` in that layout) or fall back to `router.replace` to the list when `router.canGoBack()` is false.

## State, storage, auth and offline (see [file](04-state-storage-auth-offline.md))

**Q40. Server state vs client state?**
Server state belongs to the backend and can go stale (bills, events): manage it with a cache such as TanStack Query. Client state belongs to the app (filters, open sheets): `useState`, context or Zustand.

**Q41. What must you wire up for TanStack Query on mobile?**
`onlineManager` to NetInfo and `focusManager` to `AppState`, so queries pause offline and refetch when the app returns to the foreground.

**Q42. Context or Zustand?**
Context for rarely changing values (session, theme); Zustand for shared state that changes often, because selectors re-render only subscribed components.

**Q43. AsyncStorage vs SecureStore vs MMKV?**
AsyncStorage: unencrypted, async, fine for preferences and caches. SecureStore: Keychain/Keystore-backed, small secrets like refresh tokens. MMKV: synchronous and very fast via JSI, optional encryption, needs a development build.

**Q44. Where do you keep auth tokens?**
The short-lived access token in memory; the refresh token in SecureStore; the server stores only a hash of the refresh token so it can rotate and revoke it.

**Q45. What is refresh token rotation?**
Every refresh returns a new refresh token and invalidates the old one; reuse of an old token signals theft, and the server revokes the token family.

**Q46. Why make token refresh single-flight?**
Parallel 401s would each refresh with the same token; with rotation, the second looks like reuse and the server logs the user out. One shared refresh promise avoids it.

**Q47. What happens on logout?**
Revoke the refresh token on the API, delete local tokens, clear the query cache and persisted user data, unregister the push token, cancel local notifications, reset navigation.

**Q48. Are biometrics authentication?**
No, they prove the device owner is present and unlock local data or a stored token. Server authentication still uses tokens.

**Q49. Why PKCE for OAuth on mobile?**
Mobile apps cannot keep a client secret. PKCE binds the authorization code to a verifier only the app knows, so an intercepted code is useless.

**Q50. How do you queue mutations offline with TanStack Query?**
Mutations pause while offline and resume on reconnect; persist the cache and register mutation functions with `setMutationDefaults` so paused mutations survive restarts; send idempotency keys.

**Q51. What is an idempotency key?**
A unique value per user action sent with a request, so the server can recognize retries and return the original result instead of creating duplicates.

**Q52. How do you integrate React Hook Form with `TextInput`?**
Wrap each input in `Controller` and map `field.onChange` to `onChangeText`, `field.onBlur` to `onBlur`, `field.value` to `value`; submit with `handleSubmit(onSubmit)` from a `Pressable`.

## Push notifications (see [file](05-push-notifications.md))

**Q53. What are the steps of push end to end?**
Permission, push token, send the token to the backend, store per user and device, send from a background job via the Expo Push API or APNs/FCM, handle tickets and receipts, handle the tap in the app.

**Q54. How do you get an Expo push token?**
`Notifications.getExpoPushTokenAsync({ projectId })` after permission is granted, with `projectId` from `Constants.expoConfig?.extra?.eas?.projectId`.

**Q55. APNs vs FCM credentials?**
APNs uses a `.p8` key (Key ID, Team ID) that does not expire; FCM HTTP v1 uses a Google service account. EAS stores both for the Expo push service.

**Q56. Why do foreground notifications not appear?**
No `setNotificationHandler`. By default nothing is displayed while the app is in the foreground.

**Q57. How do you handle a tap that launched a killed app?**
Read the last notification response at startup (`getLastNotificationResponseAsync()` or `useLastNotificationResponse()`), in addition to `addNotificationResponseReceivedListener` for running apps.

**Q58. What is special about Android 13+ notification permission?**
It is a runtime permission (`POST_NOTIFICATIONS`), and the prompt only appears after the app has created a notification channel.

**Q59. Why plan Android channels carefully?**
Users control each channel, and the app cannot raise a channel's importance after creating it. Separate channels (payments, events, tasks) let users mute one category without losing rent reminders.

**Q60. How many messages per Expo Push API request?**
Up to 100. Tickets come back in the same order; receipts are fetched later with up to 1000 IDs per request.

**Q61. What do you do with `DeviceNotRegistered`?**
Stop sending to that token: mark it disabled or delete it. The app was uninstalled or the token is invalid.

**Q62. Why fan out one Sidekiq job per chunk?**
Jobs run at least once; if a single job sending 50 chunks fails at chunk 30, its retry resends chunks 1 to 29. One job per chunk limits retries to the failed chunk.

**Q63. How do you test push notifications?**
On a development build on a physical device, using Expo's push tool or curl, covering foreground, background, killed and logged-out states, permission denial and reinstalls. Final check on a TestFlight build because production APNs differs.

## Payments and split bills (see [file](06-payments-and-split-bills.md))

**Q64. How do you store money?**
As integer minor units (cents) plus an ISO 4217 currency code, for example `6500` and `EUR`. Never floats.

**Q65. Why can't rent be paid with Apple in-app purchase?**
In-app purchase is for digital goods and features used in the app. Rent is a real-world service consumed outside the app, which Apple and Google require to be paid through other methods (card, Apple Pay, bank transfer).

**Q66. Who decides that a payment succeeded?**
The server, based on the provider's signed webhook (or a server-side status check). The app only shows "submitted" or "processing".

**Q67. Why must the amount come from the server?**
Client requests can be modified. The API looks up the charge, checks ownership and uses the stored amount when creating the PaymentIntent.

**Q68. What is 3D Secure?**
The card authentication step that implements SCA under the EU's PSD2. The bank may challenge the user; the payment SDK handles it, with a return URL for banking app redirects.

**Q69. Why does SEPA Direct Debit need a `processing` state?**
Confirmation takes days and payers can dispute debits for weeks, so the charge is neither paid nor failed for a while.

**Q70. How do you process webhooks safely?**
Verify the signature, store event IDs under a unique index to drop duplicates, process in a job with a row lock, and guard transitions because events arrive out of order. Reconcile daily.

**Q71. How do you split EUR 100 three ways?**
Largest remainder method in cents: 10000 / 3 floors to 3333 each, leaving 1 cent, which goes to the largest remainder (ties broken deterministically): 3333, 3333, 3334.

**Q72. How do you compute balances in a house?**
For each bill, add the total to the payer and subtract each share from its participant; settlements add to the payer and subtract from the receiver. Balances sum to zero.

**Q73. Is greedy settle-up optimal?**
It needs at most n - 1 transfers but is not always minimal. The true minimum requires the largest partition into zero-sum groups, which is NP-hard in general.

## Performance and animations (see [file](07-performance-and-animations.md))

**Q74. What is the frame budget?**
About 16.7 ms per frame at 60 Hz and 8.3 ms at 120 Hz, shared by your JS work and native rendering.

**Q75. Where do you measure performance?**
In a release or preview build on a low-end Android phone, with the Perf Monitor (JS vs UI FPS), the React Profiler in React Native DevTools and native profilers.

**Q76. Top FlatList optimizations?**
Stable `keyExtractor`, memoized `renderItem` and `memo` rows, `getItemLayout` for fixed heights, tuned `initialNumToRender`, `maxToRenderPerBatch` and `windowSize`, light rows, sized images, pagination.

**Q77. What does FlashList do differently?**
It recycles row views for new items instead of unmounting and mounting them, which is faster; recycled rows keep local state, so reset or key it by item.

**Q78. Why does `memo` sometimes not help?**
The parent passes new function or object props on every render (inline arrows, inline styles), so the shallow comparison fails.

**Q79. What does `useNativeDriver: true` do?**
Runs an Animated animation on the UI thread without JS per frame; it supports only non-layout props such as `transform` and `opacity`.

**Q80. Animated vs Reanimated?**
Animated is built in and fine for simple fades and slides. Reanimated runs animation and gesture logic as worklets on the UI thread with shared values, animates any style and suits gesture-driven UI.

**Q81. What is a worklet?**
A small JS function that Reanimated runs on the UI thread, such as a gesture callback or the function passed to `useAnimatedStyle`.

**Q82. Why use react-native-gesture-handler?**
It recognizes gestures natively and, with Reanimated, runs gesture callbacks on the UI thread, so dragging stays smooth when JS is busy; PanResponder runs on the JS thread.

**Q83. What does React Compiler change?**
It memoizes components and values automatically, so manual `useMemo` and `useCallback` everywhere becomes unnecessary where it is enabled (recent Expo SDKs can turn it on; check the docs).

**Q84. How do you improve startup time?**
Hermes bytecode, less work before the first frame, cached data instead of network waits, lazy-loaded heavy modules and SDKs, fonts embedded at build time.

**Q85. Name three causes of memory leaks in React Native.**
Listeners and timers without cleanup, subscriptions or sockets never closed, unbounded caches, and full-size images kept in memory.

## EAS Build, Submit and Update (see [file](08-eas-build-submit-update.md))

**Q86. What do EAS Build, Submit and Update do?**
Build signed binaries in the cloud, upload them to the stores, and ship JS and asset updates over the air to installed apps.

**Q87. What are typical eas.json build profiles?**
`development` (dev client, internal), `preview` (release build for QA, internal distribution, staging), `production` (store builds, auto-incremented build numbers). Each sets a channel and environment.

**Q88. `version` vs `buildNumber` vs `versionCode`?**
`version` is user-facing; iOS `buildNumber` and Android `versionCode` identify individual builds and must increase with every upload. EAS can manage them remotely with `autoIncrement`.

**Q89. What does an iOS provisioning profile contain?**
The app ID, the signing certificate, entitlements (push, associated domains) and, for ad hoc builds, the allowed device IDs.

**Q90. What is Play App Signing?**
Google holds the app signing key and re-signs your uploads; you sign uploads with an upload key that can be reset if lost.

**Q91. What are the Google Play testing tracks?**
Internal (up to 100 testers, minutes), closed, open and production, with staged percentage rollouts in production.

**Q92. What can an OTA update change?**
JS code and bundled assets: logic, screens, styles, copy, images. Not native code, native libraries, permissions, icon, name, config plugins or the SDK version.

**Q93. What is a runtime version?**
A label for a build's native layer; updates reach only builds with the same runtime version, so JS that needs new native code never reaches binaries without it.

**Q94. Which runtime version policies exist?**
`appVersion`, `nativeVersion`, `fingerprint` (a hash of the native layer) and a manual string.

**Q95. Channels vs branches?**
A build listens to a channel set at build time; updates are published to branches; a channel points to a branch and can be repointed without rebuilding.

**Q96. How do you roll back a bad OTA update?**
Republish the last good update so it becomes the newest on the branch, or roll the channel back to the embedded bundle (`eas update:republish`, `eas update:roll-back-to-embedded` in recent eas-cli versions).

**Q97. How do you force users onto a new binary?**
The API returns a minimum supported version; the app compares it with `Application.nativeApplicationVersion` and blocks with a store link. The API can also reject unsupported versions with `426 Upgrade Required`.

## Native modules, permissions, testing and debugging (see [file](09-native-modules-permissions-testing.md))

**Q98. When do you write a custom native module?**
When no Expo module or maintained library covers the need; then a local module with the Expo Modules API (`npx create-expo-module@latest --local`), used through a development build.

**Q99. How does the iOS permission prompt differ from Android's?**
iOS shows it once per permission and needs a usage string in Info.plist; Android requests dangerous permissions at runtime and stops showing the prompt after two denials (Android 11+).

**Q100. What happens if an iOS usage description string is missing?**
The app crashes when it requests that permission, and review may reject vague strings.

**Q101. How do you handle a permanently denied permission?**
Detect `canAskAgain === false`, explain why the feature needs it, offer `Linking.openSettings()`, re-check when the app returns to the foreground and provide a fallback.

**Q102. Where must `TaskManager.defineTask` be called?**
At module scope, because the OS can start your JS for a background task without mounting any screen.

**Q103. What are the AppState values?**
`active`, `background`, and `inactive` on iOS (transitions such as the app switcher or an incoming call).

**Q104. Why upload source maps?**
Production JS is minified; source maps let the crash reporter show original files, lines and function names. Each build and each EAS Update needs its own.

**Q105. How do you start debugging a production crash?**
Scope it: platform, app version, update ID, devices and when it started versus releases. Then read the symbolicated stack and breadcrumbs, reproduce in a release build, mitigate and fix.

**Q106. What is an ANR?**
"Application Not Responding" on Android: the main thread was blocked too long, so the system offers to close the app. Play Console tracks ANR rates.

**Q107. What does `jest-expo` provide?**
A Jest preset with Babel config, platform-aware module resolution and mocks for many Expo native modules.

**Q108. Maestro or Detox?**
Maestro: YAML flows, black-box, quick to write. Detox: JS tests with gray-box synchronization, more control and more setup. Both run against real builds.

## Spot the bug and what's the output

**Q109. Spot the bug: `<View>{bills.length && <BillList bills={bills} />}</View>`**
With an empty array, `0` renders as raw text inside a `View`, which crashes with "Text strings must be rendered within a <Text> component". Use `bills.length > 0 && ...` or a ternary.

**Q110. What is logged? `console.log(0.1 + 0.2 === 0.3, 10 + 20 === 30);`**
`false true`. Floating-point decimals are inexact, integer cents are exact, which is why money is stored in minor units.

**Q111. Spot the bug:**
```ts
useEffect(() => {
  AppState.addEventListener('change', (s) => s === 'active' && refetch());
}, []);
```
The subscription is never removed, so every mount adds another listener (duplicate refetches and a leak), and the stale `refetch` closure can outlive the component. Store the subscription and return `() => sub.remove()`, listing `refetch` in the dependencies.

**Q112. Spot the bug:**
```ts
const apiUrl = process.env[`EXPO_PUBLIC_${env}_API_URL`];
```
Expo inlines only static `process.env.EXPO_PUBLIC_...` references, so this dynamic lookup is `undefined` in the app. Reference each variable explicitly, or choose values in `app.config.ts`.

**Q113. Spot the bug: `Animated.timing(height, { toValue: 200, duration: 300, useNativeDriver: true }).start();`**
`height` is a layout property, which the native driver does not support, so it throws. Animate a `transform` (such as `scaleY`) with the native driver, use `useNativeDriver: false`, or use Reanimated.

**Q114. Spot the bug: `const { id } = useLocalSearchParams(); const bill = bills.find((b) => b.id === id);`**
Route params are strings while `b.id` is a number, so `find` never matches. Convert with `Number(id)` (and validate it) before comparing.

**Q115. What is wrong with publishing this as an OTA update? "Adds react-native-mmkv and replaces AsyncStorage."**
MMKV contains native code that existing binaries lack, so the update would crash on launch for those users. It needs a new store build with a new runtime version; only JS-only changes can ship over the air.
